## 1. Τι είναι

Multi-tenant SaaS για ελληνικές εταιρίες ενοικίασης αυτοκινήτων. Κάθε εταιρία (`Tenant`) έχει στόλο, πελάτες, κρατήσεις, τιμολόγια και χρήστες. Πάνω από όλα υπάρχει Super Admin πλατφόρμας.

**Stack:** Next.js 14.1.3 (App Router) · React 18 · TypeScript · Prisma 5.22 · PostgreSQL (Supabase) · JWT με `jose` · bcryptjs (12 rounds) · zod · lucide-react · καθαρό CSS (όχι Tailwind).

## 2. Πού ζει — και η ροή deploy

- **GitHub:** `giannispirenis123-source/fleetpro-v2`, branch `main`
- **Vercel:** auto-deploy σε κάθε push στο `main`
- **Supabase:** η PostgreSQL. Ο Giannis δουλεύει **μόνο από κινητό/browser** — ο agent **δεν** έχει πρόσβαση σε Supabase/Vercel.

**Η ροή είναι πάντα η ίδια και δεν παρακάμπτεται:**

1. Ο agent γράφει τον κώδικα **και** αρχείο `prisma/sql/NN-*.sql` (idempotent).
2. Δίνει το SQL στη συζήτηση, σε **ένα** block.
3. Ο Giannis το τρέχει στο **Supabase SQL Editor** και επιβεβαιώνει το verification SELECT.
4. **Μόνο τότε** λέει «push».

Push πριν το SQL = σπασμένη παραγωγή (ο κώδικας ζητά στήλες που δεν υπάρχουν).

### 3.1 Supabase Storage

- **Bucket:** `fleetpro-files` (το όνομα είναι σταθερά στον κώδικα: `STORAGE_BUCKET` στο `src/lib/storage.ts`).
- **Ρυθμίσεις:** Public bucket = **OFF** (ιδιωτικό) · Restrict file size = **5 MB** · Allowed MIME types = `image/jpeg, image/png, image/webp`.
- **Policies (RLS):** καμία. Ο server μιλά με service role, που παρακάμπτει τις policies· χωρίς policies κανείς άλλος (anon/authenticated) δεν διαβάζει ή γράφει.
- **Διαδρομές:** `tenantId/contractId/pickup|return/<τυχαίο>.jpg` για συμβόλαια, `tenantId/damages/damageId/<τυχαίο>.jpg` για ζημιές, `tenantId/branding/logo-<τυχαίο>.<png|jpg|webp>` για το λογότυπο, `tenantId/contractId/licenses/<driverId>-<front|back>-<τυχαίο>.jpg` για διπλώματα.
- Προβολή μόνο με **signed URLs** που βγαίνουν σε κάθε φόρτωση σελίδας: 1 ώρα (ζημιές/λογότυπο στο dashboard), **10 λεπτά** για διπλώματα και για ό,τι δείχνει η σελίδα πελάτη.
- `NEXT_PUBLIC_APP_URL`: **δεν χρησιμοποιείται πια** για το link πελάτη/QR (branch PR #16). Το link βγαίνει από το domain όπου δουλεύει ο χρήστης (`window.location.origin` στη φόρμα, host του αιτήματος για το QR του Α4) — σωστό σε production και preview. Μια παλιά/λάθος τιμή (το `SETUP.md` έλεγε `https://your-repl.replit.app`) έστελνε πιθανότατα τον πελάτη σε άσχετη σελίδα. Μπορεί να σβηστεί από το Vercel· δεν πειράζει αν μείνει.

## 4. Το μοτίβο για νέα σελίδα

```
prisma/schema.prisma  →  prisma/sql/NN-*.sql  →  src/lib/<feature>.ts (DTO)
  →  src/app/api/<feature>/route.ts (+ [id]/route.ts)
  →  src/app/(dashboard)/dashboard/<feature>/page.tsx (server)
  →  .../<feature>Client.tsx  →  permissions.ts  →  el.ts + en.ts  →  dashboard.css
```

### Κρίσιμα gotchas

- **Prisma:** μόνο `import { db } from "@/lib/db"` (named export).
- **Decimal → `Number()`** πριν περάσει σε client component.
- **`getSession()` async**, μόνο σε server components. Σε API routes: `getSessionFromRequest`.
- **API routes:** πάντα `export const dynamic = "force-dynamic"`.
- **Τα route files δέχονται ΜΟΝΟ συγκεκριμένα exports** (GET/POST/PATCH/DELETE/dynamic). Helpers και zod schemas → `src/lib/*Form.ts`. Το typecheck **δεν** το πιάνει, μόνο το `npm run build`.
- **Δικαιώματα, όχι ρόλοι:** `withPermission(handler, "key")` στα API, `pageGuard("key")` στις σελίδες. Διαβάζουν από τη **βάση** σε κάθε αίτημα (όχι από το JWT), οπότε αλλαγή ισχύει αμέσως.
- **Ο server ξαναϋπολογίζει κάθε ποσό** από ids. Τα zod schemas δεν έχουν καν πεδία ποσών — ό,τι στείλει ο client αγνοείται.
- **Tenant-scoped παντού:** το `tenantId` πάντα από το session.
- **Στεγανότητα PARTNER:** `bookingScope(viewer)` στο ερώτημα, όχι στο UI.
- **CSS:** `dash-*` στο dashboard, `sa-*` στο super-admin, `login-*` στο login. Μεταβλητές στο `globals.css`.
- **i18n:** το `en.ts` τυποποιείται πάνω στο `el.ts` — κλειδί που λείπει σπάει το typecheck.
- **Μετά από αποθήκευση ρύθμισης:** `router.refresh()`, αλλιώς το Router Cache δείχνει τα παλιά.
- **Ημερομηνίες:** σύγκριση ως κείμενο `"YYYY-MM-DD"`. Προσοχή: κάποιες στήλες είναι `timestamp` με ώρα μέσα στην ημέρα — άνω όριο εύρους = **αρχή της επόμενης ημέρας**, όχι μεσάνυχτα της τελευταίας.
- **Demo δεδομένα:** ΜΗΝ τα αγγίζεις (ids `demo-%`).

**Γνωστές συμπεριφορές (σκόπιμες):**
- Η προμήθεια συνεργάτη μένει πάνω στις γραμμές της κράτησης, **όχι** στη χειροκίνητη τιμή.
- Χειροκίνητη τιμή = **τιμή ΕΝΟΙΚΙΟΥ** (μόνο η βάση). Σύνολο = ενοίκιο + πρόσθετα + ασφάλεια − έκπτωση· πρόσθετα που μπαίνουν/βγαίνουν αλλάζουν αμέσως το σύνολο. Φόρμα, Α4 και σελίδα πελάτη: «Ενοίκιο» = το χειροκίνητο, οι γραμμές αθροίζουν στο σύνολο, καμία «Προσαρμογή». Λόγος/ποιος μόνο στη φόρμα.
- Πλήρης αριθμός κάρτας: κρυπτογραφημένος, «Εμφάνιση» **μόνο** για COMPANY_ADMIN· Α4/σελίδα πελάτη/searchText/logs μόνο τα 4 τελευταία (ή τίποτα).
- Φωτογραφίες διπλώματος: **μόνο** στη φόρμα — ποτέ σε Α4, σελίδα πελάτη ή `searchText`.
- Νέο (walk-in) συμβόλαιο: τίποτα δεν γράφεται στη βάση ή στο Storage μέχρι την πρώτη «Αποθήκευση».
- Demo tenant: όνομα «Fleet-Pro Car Rental», το slug μένει `p-rentals`.

**Σημειώσεις λογικής:**
- ΦΠΑ **inclusive**: το `Booking.total` περιέχει ΦΠΑ. `net = total / (1 + ΦΠΑ/100)`. Το ποσοστό γίνεται snapshot στο τιμολόγιο.
- Αρίθμηση τιμολογίων `INV-001…` ανά tenant, ασφαλής σε ταυτόχρονη έκδοση — **μένει στη βάση αλλά δεν εμφανίζεται πια**: παντού (οθόνες, PDF, email, Κρατήσεις/Ημερολόγιο) φαίνεται ο τυχαίος `invoiceCode` (§5.1).
- Προμήθεια: **δυναμική** (δεν παγώνει), πάνω σε ενοίκιο/πρόσθετα/ασφάλεια κατ' επιλογή, **πριν** την έκπτωση. Οι ακυρωμένες δεν μετράνε.
- `partnerId` = ποιος **έφερε** την κράτηση · `createdById` = ποιος την **κατέγραψε**.
- Εκπτώσεις συνδρομών (Super Admin): ποσοστό ή σταθερό €/μήνα σε **μία** εταιρία, `validFrom` → `validUntil` (κενό = μέχρι διακοπής) + `active`. **Μία ενεργή ανά εταιρία** σε επικαλυπτόμενο διάστημα (409). Οι τιμές πλάνων (`PLAN_PRICES`) ζουν πλέον στο `src/lib/platformDiscounts.ts` — το Tenant αποθηκεύει μόνο το πλάνο. **Μόνο αποθήκευση/εμφάνιση**, καμία χρέωση· το Stripe θα τις διαβάσει αργότερα. Το παλιό `PlatformCoupon` (κουπόνια με κωδικό) μένει αχρησιμοποίητο.
- Οικονομικά: **έσοδα = τιμολόγια `PAID` με `paidAt` στο διάστημα, σε `subtotal` (καθαρό, χωρίς ΦΠΑ)** — όχι `total`, ώστε το κέρδος να μη φουσκώνει από το ΦΠΑ. Κέρδος = έσοδα χωρίς ΦΠΑ − έξοδα. Το `Expense.type` μένει **ελεύθερο κείμενο** στη βάση· οι 7 τύποι (`insurance, service, fuel, salary, rent, marketing, other`, πεζά) ελέγχονται στο zod (`src/lib/finance.ts`), και άγνωστη τιμή μετρά ως «other».   - **Σφάλματα Storage (συγκεκριμένα, ασφαλή):** κάθε αποτυχία γίνεται `StorageError` με κωδικό, και ο server απαντά `{ message, code }`. Το UI δείχνει το `message` στην ουρά ανεβάσματος (με «Ξανά»):

    | Αιτία | `code` | HTTP | Μήνυμα (σύνοψη) |
    |---|---|---|---|
    | Λείπει env var | `CONFIG_MISSING` | 503 | «Λείπει η μεταβλητή SUPABASE_… » (όνομα, ποτέ τιμή) |
    | Λάθος μορφή URL | `CONFIG_INVALID_URL` | 503 | «πρέπει να ξεκινά με https:// και να τελειώνει σε .supabase.co» |
    | Storage 401/403 | `AUTH` | 502 | λάθος κλειδί στο `SUPABASE_SERVICE_ROLE_KEY` (όχι anon/publishable) |
    | Storage 404 | `BUCKET_NOT_FOUND` | 502 | δεν βρέθηκε το bucket `fleetpro-files` (ή άλλο project) |
    | Storage 400/415 | `REJECTED_TYPE` | 415 | Allowed MIME types του bucket |
    | Storage 413 | `REJECTED_SIZE` | 413 | όριο μεγέθους του bucket |
    | Δίκτυο | `NETWORK` | 502 | δεν υπάρχει σύνδεση με το Storage |

    Η Supabase συχνά απαντά HTTP 400 με `statusCode` μέσα στο σώμα (π.χ. `"404"` + «Bucket not found»)· η κατάταξη κοιτά πρώτα αυτό. **Logs:** `Storage upload: HTTP 400 → BUCKET_NOT_FOUND — statusCode 404 · Bucket not found`· το κείμενο της Supabase περνά από `scrub()` (βγάζει URLs, JWT, `sb_secret_…`, `token=`/`key=`, `Bearer`), σε σφάλμα δικτύου γράφεται μόνο ο κωδικός (π.χ. `ECONNREFUSED`). Όταν η απάντηση δεν είναι JSON (π.χ. 413 του Vercel), το UI δείχνει μήνυμα ανά HTTP status. Τα ίδια ισχύουν για τις ζημιές της σελίδας Service.

### 5.2 Πακέτα (entitlements) και δημόσια σελίδα (branch `ccr-0edadca8-vvohvc`, SQL `20`)

Το FleetPro νοικιάζεται: κάθε εταιρία παίρνει μόνο ό,τι περιλαμβάνει το πακέτο της. **Δεν** περιλαμβάνει φόρμα κράτησης, πληρωμές ή email.

- **Πίνακας `plans`** (`key` PK, `name`, `modules` JSONB, `limits` JSONB, `active`). `modules`: μόνο το `true` ανοίγει ενότητα (`dashboard`, `publicSite`). `limits`: `maxUsers`, `maxVehicles` — αριθμός = όριο, **`null` ή απόν = απεριόριστο**. Οι τιμές **ζουν μόνο στη βάση**· αλλάζουν με UPDATE, χωρίς deploy, και ισχύουν στο επόμενο αίτημα.
- **Αρχικά πακέτα (ΠΡΟΣΩΡΙΝΕΣ τιμές):** `dashboard` (μόνο dashboard, 1 χρήστης, οχήματα ∞) · `dashboard_site` (dashboard + δημόσια σελίδα, ∞) · `full` (όλα, ∞). **Όλες οι υπάρχουσες εταιρίες (και η demo) πήραν `full`** — τίποτα δεν άλλαξε στη λειτουργία τους.
- **Στην εταιρία:** `tenants."planKey"` (FK → `plans.key`, ON DELETE SET NULL) και `tenants."entitlementOverrides"` JSONB `{"modules":{…},"limits":{…}}` — υπερισχύει του πακέτου **ανά κλειδί** (και `"maxUsers": null` = απεριόριστο μόνο για αυτήν). Το παλιό `tenants.plan` (STARTER/PRO/ENTERPRISE) **μένει** και αφορά μόνο την τιμή συνδρομής.
- **Εταιρία χωρίς πακέτο** (`planKey` null): καμία ενότητα, όριο 0 σε χρήστες/οχήματα (μήνυμα «η εταιρία δεν έχει ενεργό πακέτο»). Νέες εταιρίες από τον Super Admin παίρνουν `full` αν δεν επιλεγεί άλλο.
- **`active = false`** σε πακέτο: δεν προσφέρεται πλέον στα selects· όσες εταιρίες το έχουν το κρατούν κανονικά.
- **Κώδικας:** κανόνες στο `src/lib/entitlementsCore.ts` (καθαρή λογική, tests)· ανάγνωση από τη βάση **μόνο** στο `src/lib/entitlements.ts`: `getEntitlements(companyId)`, `hasModule(companyId, 'publicSite')`, `checkWithinLimit` / `assertWithinLimit(companyId, 'users' | 'vehicles')`. Μετρούν μόνο τα **ενεργά** (`isActive`).
- **Έλεγχοι στον server (403 με ελληνικό μήνυμα, όχι 500):** `POST /api/vehicles`, `POST /api/company-users`, `PATCH /api/company-users/[id]` (επανενεργοποίηση χρήστη), `POST /api/users` (παλιό), `/api/storefront*`, δημόσιες σελίδες. Το UI απλώς απενεργοποιεί «Νέο όχημα» / «Νέος χρήστης» με το ίδιο μήνυμα και δείχνει «Η σελίδα μου» κλειδωμένη («εκτός πακέτου»). Γνωστό όριο: σε δύο **ταυτόχρονες** δημιουργίες στο τελευταίο ελεύθερο slot μπορεί να περάσουν και οι δύο (χωρίς κλείδωμα)· αμελητέο για τώρα.
- **Αλλαγή πακέτου:** `/super-admin` → Εταιρίες → ⋮ → «Επεξεργασία» → **«Πακέτο (λειτουργίες)»** (`PATCH /api/tenants/[id]` με `planKey`, έλεγχος ότι υπάρχει). Υπάρχει και στη «Νέα εταιρία». Λίστα: `GET /api/plans` (μόνο Super Admin). Εναλλακτικά με SQL:

```sql
-- Πακέτο μιας εταιρίας (dashboard | dashboard_site | full)
UPDATE "tenants" SET "planKey" = 'dashboard_site' WHERE "id" = '<tenantId>';
-- Αλλαγή ορίων/ενοτήτων ενός πακέτου (ισχύει αμέσως για όλες τις εταιρίες του)
UPDATE "plans" SET "limits" = '{"maxUsers":3,"maxVehicles":20}', "updatedAt" = now() WHERE "key" = 'dashboard';
UPDATE "plans" SET "modules" = '{"dashboard":true,"publicSite":true}', "updatedAt" = now() WHERE "key" = 'dashboard';
-- Εξαίρεση για μία εταιρία (π.χ. +2 χρήστες, ή δημόσια σελίδα δώρο)
UPDATE "tenants" SET "entitlementOverrides" = '{"limits":{"maxUsers":3},"modules":{"publicSite":true}}' WHERE "id" = '<tenantId>';
-- Νέο πακέτο
INSERT INTO "plans" ("key","name","modules","limits") VALUES ('pro_site','Pro + Site','{"dashboard":true,"publicSite":true}','{"maxUsers":5,"maxVehicles":50}');
```

**Δημόσια σελίδα (storefront):**

Ενεργοποίηση, slug με έλεγχο διαθεσιμότητας (`GET /api/storefront/slug`), γλώσσες + προεπιλογή, κείμενα ανά γλώσσα, πληρωμή κατά την παραλαβή, online «σύντομα» (ανενεργό), link προεπισκόπησης. #### Χρεώσεις δρομολογίου και προσφορές (SQL `21c`)

**Χρεώσεις δρομολογίου ανά τοποθεσία** (`pickup_locations`, cents): `deliveryFeeCents` (ο πελάτης **παραλαμβάνει** το όχημα εκεί), `collectionFeeCents` (το **επιστρέφει** εκεί), `feeFreeFromDays` (από τόσες ημέρες και πάνω = 0), `feeLabel` (ΕΛ/EN).
- **Μεταφορά** (21c): όπου `adjustmentType = 'fixed'` με θετικό ποσό → το ποσό και στα δύο fees, `adjustmentLabel` → `feeLabel`, `adjustmentType = 'none'`, `value = 0`. Ίδιος κανόνας και στον κώδικα (`migrateLegacyFixed` στο `pricing.ts`, για γραμμές που δεν έχουν περάσει ακόμα). Αρνητικό `'fixed'` (παλιά σταθερή έκπτωση) δεν μεταφέρεται και **δεν εφαρμόζεται πια** (το verification το μετρά: `fixed_negative_left`).
- **Η έκπτωση τοποθεσίας είναι πλέον μόνο ποσοστό** (`adjustmentType` `'percent'`, αρνητικό value)· το `'fixed'` δεν εμφανίζεται στο UI (ο CHECK μένει για συμβατότητα). Θετικό ποσοστό = επιβάρυνση (γραμμή `location`).
- **quote():** κάθε σκέλος χωριστά — παραλαβή στη Χ → «Παράδοση: <feeLabel ή όνομα>» με το `deliveryFeeCents` της Χ· επιστροφή στην Υ (ή στη Χ αν δεν δόθηκε) → «Παραλαβή: …» με το `collectionFeeCents` της Υ. Ίδιο σημείο = δύο δρομολόγια, δύο γραμμές. Με `days >= feeFreeFromDays` οι γραμμές μένουν με 0 € και «(Δωρεάν από Ν ημέρες)». Το `oneWayFeeCents` και η χρέωση εκτός ωραρίου όπως πριν. Οι χρεώσεις δρομολογίου **δεν** εκπτώνονται. Σημείωση: το μεταφερμένο κείμενο του demo («Παράδοση στο Ηράκλειο») διαβάζεται περίεργα στη γραμμή «Παραλαβή: …» — καλύτερα σκέτο «Ηράκλειο» από τη φόρμα.
- **UI «Τοποθεσίες»:** στη φόρμα «Χρέωση παράδοσης εδώ (€)», «Χρέωση παραλαβής από εδώ (€)», «Δωρεάν από (ημέρες)», «Κείμενο χρέωσης ΕΛ/EN» και χωριστά «Έκπτωση τοποθεσίας (%)». Στη λίστα κάθε σημείο δείχνει «+50 € / +50 €», «-10%», και το κουμπί **«Ποσά»** ανοίγει γρήγορη επεξεργασία ποσών μέσα στη λίστα (αποθηκεύει όλη την εγγραφή με `PATCH /api/public-site/locations/[id]`).

**Προσφορές** (πίνακας `promotions`, πόρος `promotions` στο `src/lib/public/resources.ts`, `/api/public-site/promotions[/id]`): `name`/`badge` (ΕΛ/EN), `isActive`, `discountType` (`percent` 1–90 · `per_day` · `per_rental` σε cents), `validFrom`/`validTo` (**DATE**, πραγματικές ημερομηνίες, και οι δύο μέσα), `locationIds` + `locationMatch` (`pickup`/`dropoff`/`either`), `rentalGroupIds`, `vehicleIds`, `vehicleTypes`, `minDays`, `sortOrder`. **Κενή λίστα = όλα.** Ο server ελέγχει ότι τοποθεσίες/ομάδες/οχήματα είναι της ίδιας εταιρίας.
- **Ισχύει** αν: ενεργή · ταιριάζει τοποθεσία · ταιριάζει όχημα (όλες οι λίστες κενές = όλα, αλλιώς αρκεί ΕΝΑ από ομάδα/όχημα/τύπο — για όχημα μετρά και η ομάδα του) · `days >= minDays` · τουλάχιστον μία ημέρα ενοικίασης μέσα στο διάστημα (ημερολογιακές ημέρες στη ζώνη της εταιρίας).
- **Ποσό:** μόνο στο ενοίκιο των ημερών μέσα στο διάστημα — percent στο ενοίκιο εκείνων, per_day × ημέρες μέσα (ποτέ κάτω από 0 ανά ημέρα), per_rental μία φορά (έως το ενοίκιο εκείνων).
- **ΧΩΡΙΣ άθροισμα:** από την έκπτωση τοποθεσίας και όλες τις προσφορές εφαρμόζεται **μόνο η μεγαλύτερη σε €**· ισοπαλία → μικρότερη `sortOrder` (η τοποθεσία μετρά ως −1). - Extras, ασφάλεια, επιβαρύνσεις ηλικίας και χρεώσεις δρομολογίου **δεν** εκπτώνονται.
- **fromPrice()** επιστρέφει πλέον `{ dailyCents, listDailyCents, badge }` και παίρνει `{ horizonDays, promotions }`: μετρά μόνο ενεργές προσφορές **χωρίς** τοποθεσία (ποσοστό ή ανά ημέρα· η «ανά ενοικίαση» δεν εκφράζεται ανά ημέρα), για το συγκεκριμένο όχημα/ομάδα.

### 5.5 Ενιαία τιμολόγηση — μία μηχανή για dashboard και site (branch `claude/unified-pricing`, SQL `22`)

**Κανόνας:** κάθε τιμή της εφαρμογής βγαίνει από την `quote()` (`src/lib/public/pricing.ts`) μέσω της `quoteFromContext(ctx, request)` (`src/lib/public/engine.ts`). Η έκπτωση **κωδικού** του dashboard (πίνακας `discounts`) μπαίνει πάνω στο σύνολο της quote(), επίσης σε ακέραιο € (`manualDiscountCents`).

### 5.10 Online πληρωμές — Stripe Connect (branch `claude/stripe-connect-payments`, SQL `27`)

**Μοντέλο:** κάθε εταιρία συνδέει **δικό της** λογαριασμό Stripe **Express** (onboarding που φιλοξενεί το Stripe). Χρέωση **direct charge** στον λογαριασμό της εταιρίας (header `stripeAccount`) — η εταιρία είναι ο έμπορος, τα χρήματα πάνε απευθείας σε αυτήν. Προαιρετική προμήθεια πλατφόρμας `tenants."platformFeeBps"` (0 = δεν στέλνεται `application_fee_amount`)· τη βλέπει/αλλάζει **μόνο ο Super Admin** (φόρμα εταιρίας, «Προμήθεια πλατφόρμας %»). Καμία άλλη βιβλιοθήκη (μόνο το `stripe` 14.x, `apiVersion 2023-10-16`). Κανένα στοιχείο κάρτας στη βάση· το `cardNumberEnc` των συμβολαίων δεν αγγίχτηκε. Δεν υπήρχε άλλος κώδικας Stripe (τα `stripeCustomerId`/`stripeSubId` είναι για μελλοντικές συνδρομές και μένουν χωριστά).

**Βάση (SQL 27):** `tenants` + `stripeAccountId` (UNIQUE), `stripeChargesEnabled`, `stripePayoutsEnabled`, `stripeDetailsSubmitted`, `paymentOptions` (`PICKUP_ONLY` προεπιλογή | `ONLINE_OR_PICKUP` | `ONLINE_ONLY`), `onlineAmountType` (`FULL` | `DEPOSIT`), `depositPercent` (1–100), `platformFeeBps` (0–5000). `bookings` + `paymentMethod` (NULL/`PICKUP`/`ONLINE`), `paymentStatus` (`NONE`, `AWAITING_PAYMENT`, `PAID`, `FAILED`, `EXPIRED`, `REFUNDED`, `PARTIALLY_REFUNDED`), `paymentExpiresAt`. Πίνακες `booking_payments` (μία γραμμή ανά Checkout Session: ποσό/επιστροφές σε cents, `refunds` JSONB ιστορικό, CASCADE σε tenant και κράτηση) και `stripe_events` (idempotency).

**Κώδικας:** `src/lib/public/payments.ts` (καθαρό: επιλογές, ποσά, μεταβάσεις webhook, επιστροφή, ένδειξη), `src/lib/public/paymentWebhook.ts` (λογική webhook με εγχυόμενη βάση), `src/lib/public/paymentServer.ts` (Checkout, store webhook, refund, λήξη αναμονών), `src/lib/stripeConnect.ts` (client + env). Routes: `GET/PATCH /api/public-site/payments`, `POST …/payments/connect` (Express account + Account Link, επιστροφή στο `?tab=payments`), `POST …/payments/login-link` (πίνακας Express) — όλα `withPublicSite` (Admin + publicSite)· `POST /api/stripe/connect/webhook`· `POST /api/bookings/[id]/refund` (μόνο `COMPANY_ADMIN`).

**Κανόνες:**
- Online επιλογές ισχύουν ΜΟΝΟ με λογαριασμό «Ενεργό» (charges + payouts) ΚΑΙ ρυθμισμένα env (`effectivePaymentOptions`)· αλλιώς ο server τις χειρίζεται ως `PICKUP_ONLY`.
- Ποσό: από το **αποθηκευμένο** `priceQuote.totalCents` της κράτησης (ποτέ από τον browser). `DEPOSIT` = ποσοστό στρογγυλό σε ακέραιο € (half up), ελάχιστο 1 €, ποτέ πάνω από το σύνολο. EUR, γλώσσα της σελίδας Stripe από το `siteLang`.
- Φόρμα: «Πληρωμή online τώρα» / «Πληρωμή στην παραλαβή» με **καμία προεπιλογή** όταν υπάρχουν και τα δύο (κόκκινο πεδίο + μήνυμα + scroll), ποσό τώρα και υπόλοιπο. Ο server ξαναελέγχει (`resolvePaymentMethod`).
- Online: η κράτηση γράφεται `PENDING` + `AWAITING_PAYMENT` μέσα στο κλείδωμα, μετά Checkout Session (`metadata {bookingId, tenantId, bookingCode}`, `expires_at` = +31΄ — το Stripe θέλει ≥ 30΄, success → `/booking/ΚΩΔΙΚΟΣ?paid=1`, cancel → `/booking/ΚΩΔΙΚΟΣ`, idempotency key ανά κράτηση). Αποτυχία του Stripe → η κράτηση ακυρώνεται αμέσως και ο πελάτης βλέπει μήνυμα. Όριο `checkout-tenant` 30/ώρα (rate_limits).
- Η αναμονή πληρωμής **κρατά το όχημα έως τη λήξη**· μετά δεν μετρά σε **κανέναν** έλεγχο (site `availability.ts`, dashboard `bookingConflicts.ts`, walk-in `walkIn.ts` — `notExpiredHold`), ακόμα και χωρίς webhook. `expireStaleHolds` την κάνει `CANCELLED`/`EXPIRED` με λόγο `payment_not_completed` (στην υποβολή, στη σελίδα κράτησης, στη λίστα κρατήσεων).
- **PAID μόνο από το webhook** (`checkout.session.completed` με `payment_status=paid` ή `async_payment_succeeded`) και μόνο αν ποσό/νόμισμα = αναμενόμενα. `BOOKING` → `CONFIRMED`· `REQUEST` → μένει `PENDING` με «Πληρωμένο». Πληρωμή σε ήδη ακυρωμένη → PAID + ειδοποίηση «θέλει επιστροφή». Το `?paid=1` απλώς δείχνει «Επιβεβαιώνουμε…» και ανανεώνει τη σελίδα.
- Webhook: υπογραφή στο ακατέργαστο body· εταιρία ΜΟΝΟ από `event.account`· κράτηση από metadata με έλεγχο tenant/booking/session· event id στο `stripe_events` στην ίδια transaction (διπλό = «duplicate», αποτυχία = 500 και ξαναστέλνεται). Events: `checkout.session.completed`, `…async_payment_succeeded`, `…async_payment_failed`, `…expired`, `account.updated`, `charge.refunded`.
- Επιστροφή χρημάτων: ΠΟΤΕ αυτόματα· κουμπί στην κάρτα ακυρωμένης πληρωμένης κράτησης (Admin), ολόκληρο ή μερικό με επιβεβαίωση, refund στον λογαριασμό της εταιρίας (με αναλογική επιστροφή προμήθειας αν υπάρχει), ιστορικό στο `booking_payments.refunds` + `activity_logs` (`booking.refund`). Partner/Staff: 403.
- Dashboard: ένδειξη «Στην παραλαβή / Αναμονή online πληρωμής / Πληρώθηκε X από Y / Επιστράφηκαν / Δεν ολοκληρώθηκε» + link «Στο Stripe» (test/live από το κλειδί). Μήνυμα πελάτη (PR #26): «Πληρώθηκαν online X · Υπόλοιπο στην παραλαβή Y»· στην ακύρωση «θα σας επιστραφεί» ή «επιστράφηκαν».
- Σελίδα πελάτη: «Αναμονή πληρωμής» (με «Ολοκλήρωση πληρωμής» όσο ζει η συνεδρία — μόνο URL `checkout.stripe.com`), «Πληρώθηκε X €» (+ υπόλοιπο), «Η πληρωμή δεν ολοκληρώθηκε».

**Tests:** `tests/stripe-payments.test.mjs` (32, mock store, χωρίς δίκτυο): ποσά FULL/DEPOSIT/στρογγυλοποίηση/ελάχιστο, επιλογές ανά ρύθμιση και κατάσταση λογαριασμού, webhook completed/expired/async/refunded, idempotency, λάθος εταιρία → αγνόηση, ποσό διαφορετικό → όχι PAID, διαθεσιμότητα με ληγμένη αναμονή, επιστροφή (ρόλοι/όρια), μηνύματα, σελίδα κράτησης, εγγραφή, έλεγχοι κώδικα (υπογραφή, κανένα κλειδί/NEXT_PUBLIC, φύλακες). Τοπικά (01 → 27, ψεύτικα κλειδιά): φόρμα με υποχρεωτική επιλογή, αποτυχία Stripe → ακύρωση + μήνυμα, webhook με πραγματική υπογραφή (λάθος ποσό / άγνωστος λογαριασμός / applied / duplicate), PAID → CONFIRMED + ειδοποίηση, μερική επιστροφή, λήξη αναμονής χωρίς webhook, 403 σε Partner/Staff.

**Για αργότερα:** (1) Ασύγχρονες μέθοδοι (SEPA κ.λπ.) δεν ενεργοποιούνται ρητά — το Checkout δείχνει ό,τι έχει ενεργό η εταιρία· αν ολοκληρωθούν μετά τη λήξη των 31΄, η κράτηση έχει ήδη ακυρωθεί (PAID + «θέλει επιστροφή»). (2) Δεν στέλνεται email αυτόματα με την πληρωμή — η εταιρία επιβεβαιώνει/στέλνει μήνυμα όπως πριν. (3) Disputes/chargebacks δεν παρακολουθούνται (φαίνονται στον πίνακα Stripe). (4) Τιμολόγιο: δεν σημειώνεται αυτόματα το online ποσό.
